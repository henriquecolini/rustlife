## Ground rules (learned the hard way)
- Content: `--game-dir "/mnt/jupiter/Games/SteamLibrary/steamapps/common/Half-Life 2 Deathmatch"` (not auto-discovered). Inspect files with `target/release/rustlife-inspect --game-dir ... ls|cat|extract|sequences`.
- Particle systems live in `particles/*.pcf` (binary DMX) in the mounted game; materials in `materials/particle/**`, `materials/effects/**`, `materials/sprites/**`.
- Client effects the game draws in code (not PCF) are registered by name with `DECLARE_CLIENT_EFFECT` (strings like `AR2Impact`, `MuzzleFlash_*`); find the registration (xref the name string), take the callback address from the `lea rdx` before it, and read its constants. Sizes of legacy particles (`SimpleParticle`) and `FX_AddQuad` quads are half-sizes; a PCF card's `radius` is a half-size too, a PCF trail's is its full width.
- Reading the game's code: Ghidra/REA times out on `hl2mp/bin/linux64/{server,client}.so` (stripped, 18 MB). What worked: `objdump -d --no-show-raw-insn -M intel X.so > X.asm`, then find a string's address with `strings -t x`, grep `# <addr> ` in the asm for its users, and walk vtables via RTTI (typeinfo name -> typeinfo -> `R_X86_64_RELATIVE` relocs from `readelf -rW` -> vtable slots). ConVar defaults: pairs of `lea rdx,[default]` / `lea rsi,[name]` before `call` in static initialisers. Scripts were scratch files; rewrite them (small Python) if needed.

### Gravity Gun pull: findings from server.so (2026-10-27, not applied yet)
- Secondary-fire routine (`c90950` in objdump of server.so; ConVar objects: pullforce `12ace40`, tracelength `12acf80`, value float at object+0x54 via the pointer slot at object+0x38): the cone search runs along a ray of 4 x physcannon_tracelength (= 1000, not 250) with `physcannon_cone`; primary-fire punt checks use 1 x tracelength (`c8f91c`: gives up if farther than 250). So objects far beyond 250 are found and pulled, which matches the user's claim.
- The pull is `ApplyForceCenter`-like (vtable slot +0x1e0 of the VPhysics object) of `normalize(eye_hold_point - object_center) * physcannon_pullforce (4000)`, scaled by `(mass + 0.5) * 0.02` when mass < 50 kg. Unverified: whether that force is per tick (acceleration = F/m) and how it relates to our `pull_speed: 500`; measure in native HL2DM (see ground truth) before replacing `pull_speed` with a force model.
- Not read yet: the near/far split that decides grab vs pull (`c90d4x` compares against 4 x tracelength squared, but `c8ff40` has its own checks), hold distance (CGrabController), refire times.
